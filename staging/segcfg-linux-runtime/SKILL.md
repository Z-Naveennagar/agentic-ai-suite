Guide the user through booting Linux on a Versal Segmented Configuration board and loading the PLD PDI at runtime.

## Instructions

1. Read `${CLAUDE_SKILL_DIR}/references/fpgautil-guide.md` for fpgautil command syntax, dtbo requirements, and PL reload procedure.

2. Ask the user:
   - Their boot method: JTAG boot via petalinux-boot, SD card, or TFTP
   - Whether they are loading PLD for the first time or performing PL Reload
   - Whether they have a second PLD PDI variant for reload testing

3. **Boot Linux via JTAG** (for initial development and testing):
   ```bash
   # Step 1: Start the hardware server on the host machine
   xsdb
   xsdb% hw_server

   # Step 2: Set TFTP root to PetaLinux images directory (host side)
   tftpd "<path_to_petalinux_project>/images/linux"

   # Step 3: Open serial console for UART0 (baudrate 115200)

   # Step 4: Boot Linux via JTAG
   petalinux-boot --jtag --u-boot --hw_server-url <HostMachineName>:3121
   ```
   Linux boot messages appear on the UART console. Log in as `petalinux` (set password on first login).

4. **Load the PLD PDI from Linux**:
   ```bash
   # Load PLD PDI with device tree overlay
   sudo fpgautil -b /lib/firmware/<pld-firmware-app-name>.pdi \
                 -o /lib/firmware/<dtbo-name>.dtbo
   ```
   The `-b` flag specifies the PDI bitstream; `-o` specifies the device tree overlay.
   After this command, the PL domain is fully configured and its memory space is accessible.

5. **Verify PL access after loading**:
   ```bash
   # Read PL-mapped memory (e.g., BRAM at AXI address 0xa4000000)
   devmem 0xa4000000
   # Expected output: 0x00000000

   # Write to PL memory
   devmem 0xa4000000 32 0xdeadbeef

   # Verify write
   devmem 0xa4000000
   # Expected output: 0xDEADBEEF
   ```

6. **PL Reload** (loading a different PLD image):
   ```bash
   # Step 1: Remove the existing PL image (REQUIRED before reprogramming)
   sudo fpgautil -R

   # Step 2: Load the new PL image
   sudo fpgautil -b /lib/firmware/<second_design>_pld.pdi \
                 -o /lib/firmware/<dtbo-name>.dtbo
   ```
   PLM automatically applies isolation at the PS-PL boundary, reconfigures PL, and releases isolation.
   After reload, drivers for changed IP may need to be unloaded and reloaded.

7. **Verify after PL Reload**:
   ```bash
   # Memory content depends on the new PL image
   sudo devmem 0xa4000000
   # If new image has reset BRAM: 0x00000000
   ```

8. **Runtime management considerations**:
   - Pause user application activity before initiating PL Reload
   - Unload kernel drivers for PL-based peripherals before reload; reload after
   - Address mappings may change if the new PL image differs significantly
   - CPM Root Port: must be held in reset for the duration of a PL Reload event

9. **Booting from SD card** (production flow):
   - Copy `boot.bin`, `boot.scr`, `image.ub` to the SD card FAT partition
   - Place `<design>_pld.pdi` and `.dtbo` files in the rootfs at `/lib/firmware/`
   - Board boots automatically; PLD loading is triggered by the dfx-mgr daemon or manual fpgautil call

10. Remind the user:
    - `fpgautil` requires the dfx-mgr package to be installed (enabled in PetaLinux/Yocto config)
    - The device tree overlay (.dtbo) is generated by the PetaLinux firmware app or Yocto recipe
    - For more on fpgautil, refer to [UG1144 - PetaLinux Tools Reference Guide]
